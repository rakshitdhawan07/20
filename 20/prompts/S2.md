## Notes on the decomposition

The tasks were done in the order b, c, a rather than a, b, c, because that is
the order of dependency: the helpers come before the function that uses them,
the direct version before the higher-order version that replaces it, and the
input-reading wrapper last, once there was something for it to call. S2.a is
the smallest of the three and depends on both of the others.

Doing S2.b before S2.c, and deleting the S2.b definition when S2.c replaced
it, follows the problem statement, which asks for `insert-if-short` to be
defined with the helpers and then changed so that it is defined using
`make-inserter`. The intermediate version was real, was checked against the
worked examples, and was then removed; the two commits are the record of that.

Two constraints shaped every unit and are documented in the code:

- `my-length` is called once per list, never once per element, because the
  hidden tests use lists of 10,000 elements and the per-element version is
  quadratic.
- an element counts as a list when it is `'()` **or** a pair. Testing `pair?`
  alone treats `'()` as an atom, which breaks the rule that `'()` has length 0
  and becomes `(x)` whenever `0 < n`.

The prompt that was deliberately not asked: "write 20_q4.rkt", or any prompt
covering more than one of S2.a, S2.b and S2.c at once.
