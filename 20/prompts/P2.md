## 4 — verification follow-up

> Some issue gave all bad

Sent with `code/20_q2.pl` attached, after a check of the eight
parenthesisation examples reported every case as failing.

- **Unit:** diagnosing the failure. No change to the solution.
- **Outcome:** the fault was in the check, not the code. It compared the
  printer's output, an SWI-Prolog string, against an expected value written as
  an atom, and `"(4+2)*3" == '(4+2)*3'` is false on type alone. Replacing the
  comparison with `atom_string/2` made all eight cases pass. No commit; the
  episode is recorded here because the brief asks for every prompt used.

## Notes on the decomposition

The four build units follow the data: generate candidate trees, give them
values, give them a written form, then select and present the valid ones. Each
unit could be counted or compared before the next was written — the generator
by the number of trees it yields, the evaluator by how many of those trees
have a value, the printer against the eight worked examples in the problem
statement, and only then the equations themselves.

Asking for `generate_equation/2`, `all_equations/2` and `count_equations/2` in
a single prompt is three predicates, but they are three one-line wrappers over
the same `valid_equation/2` and share a single idea, so they are one unit of
work rather than three.

The prompt that was deliberately not asked: "write 20_q2.pl", or anything else
that would have requested the whole problem at once.
